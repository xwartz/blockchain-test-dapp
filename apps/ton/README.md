# TON Wallet Test DApp

A complete React application implementing a TON (The Open Network) wallet with full TON Connect protocol support via HTTP Bridge.

## 🌟 Features

- **TON Wallet Management**: Create and import TON wallets
- **TON Connect Protocol**: Full HTTP Bridge implementation
- **dApp Connection Handling**: Correctly handles dApp-generated connection URLs
- **Transaction Signing**: Send and sign TON transactions
- **TON API Integration**: Powered by [tonapi.io](https://tonapi.io) for reliable blockchain data
- **Modern UI**: Built with Tailwind CSS and Shadcn UI components
- **Type Safety**: Full TypeScript implementation

## 🚀 Quick Start

```bash
# Install dependencies from the root
pnpm install

# Start development server (runs on port 3004)
pnpm dev:ton

# Build for production
pnpm build --filter=ton
```

## 📱 Usage

### 1. Create/Import Wallet

1. Open http://localhost:3004 in your browser
2. Click "Generate New Wallet" or import existing mnemonic
3. The wallet will be created and HTTP Bridge will start listening

### 2. Connect to dApps (Correct Flow)

1. **From the dApp side**: dApp generates a connection URL
2. **Copy the URL**: Copy the connection URL from the dApp
3. **Paste in wallet**: Paste the URL in the "dApp Connection URL" field in your wallet
4. **Approve connection**: Click "Connect to dApp" and approve the connection request

### 3. Sign Transactions

1. Connected dApps can request transaction signing
2. Review transaction details in confirmation dialog
3. Approve or reject transactions

## 🔧 TON Connect Implementation

This wallet implements the **correct** TON Connect protocol with proper role separation:

### Protocol Flow (Corrected)

1. **dApp generates URL**: dApp creates connection request with session ID and manifest
2. **User transfers URL**: User copies URL from dApp and pastes in wallet
3. **Wallet processes URL**: Wallet parses URL, shows connection request
4. **User confirms**: User approves/rejects connection in wallet
5. **Wallet responds**: Wallet sends response via HTTP Bridge to dApp

### HTTP Bridge Architecture

- **Bridge URL**: `https://bridge.tonapi.io/bridge`
- **EventSource**: Real-time message listening for both dApp and wallet
- **Request Handling**: dApps send connection/transaction requests
- **Response Protocol**: Wallet sends responses back via bridge

### Supported Methods

- `connect` - Wallet connection with address and proof
- `sendTransaction` - Transaction signing and broadcasting

## 🛠️ Implementation Details

### Correct Role Separation

- **dApp**: Generates connection URLs, sends transaction requests
- **Wallet**: Processes URLs, shows confirmations, sends responses
- **Bridge**: Routes messages between dApp and wallet

### Connection URL Format

```
https://app.tonkeeper.com/ton-connect?v=2&id=<session_id>&r=<encoded_request>
```

Where `r` parameter contains:

```json
{
  "manifestUrl": "https://dapp.com/manifest.json",
  "items": [{ "name": "ton_addr" }, { "name": "ton_proof", "payload": "..." }]
}
```

### Message Flow

1. **dApp → Bridge**: Connection/transaction requests
2. **Bridge → Wallet**: Forward requests via EventSource
3. **Wallet → User**: Show confirmation dialogs
4. **Wallet → Bridge**: Send approved responses
5. **Bridge → dApp**: Forward responses

### API Configuration

The wallet uses [tonapi.io](https://tonapi.io) for blockchain data access:

- **Endpoint**: `https://tonapi.io`
- **Authentication**: Bearer token authentication
- **Features**: Account balances, transaction data, network information
- **Fallback**: Automatic fallback to standard TON client if API fails

You can configure the API settings in `src/utils/ton/config.ts` or via environment variables:

```bash
VITE_TONAPI_ENDPOINT=https://tonapi.io
VITE_TONAPI_TOKEN=your_api_token_here
VITE_TON_NETWORK=mainnet
```
